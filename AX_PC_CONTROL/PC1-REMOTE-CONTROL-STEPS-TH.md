# ให้ OpenHands คุม PC1 — ขั้นตอนทำจริง (ฉบับทำที่เครื่อง)

เอกสารนี้คือสิ่งที่ต้องทำ **ที่ PC1** ตอนนี้ที่คุณนั่งอยู่หน้าเครื่อง
เรียงตามลำดับ ทำจากบนลงล่าง ไม่ต้องข้าม

## สถานะที่ตรวจมาแล้ว (หลักฐานจริง)

- งานทุกตัวที่ต้องใช้ runner บน PC1 **ค้างอยู่ในคิวตั้งแต่ 19 ต.ค.** (สถานะ `queued`)
  → แปลว่า runner บน PC1 **ไม่ได้ทำงานอยู่** นี่คือสาเหตุที่ทุกทางเข้ามาตัน
- workflow ใหม่ `AX PC1 Desktop Control` สั่งงานได้แล้ว (ตอบ 204) แต่ **ค้างคิว** ด้วยเหตุเดียวกัน
- workflow `AX PC1 Tailnet Reach` รันแล้ว **ล้มเหลว** เพราะขาด `TS_AUTHKEY`
  (ตัวนี้รันบนเครื่อง GitHub ไม่ใช่ PC1 จึงไม่ได้ทดสอบ PC1 จริง)
- แก้บั๊กที่เจอแล้ว: workflow ที่มีแต่ `workflow_dispatch` บนสาขาย่อย
  **GitHub จะไม่ลงทะเบียนให้** จึงสั่งงานไม่เคยได้ (404 ตลอด) แก้โดยใส่ trigger `push`
  แคบ ๆ เฉพาะไฟล์ workflow เอง → ตอนนี้ลงทะเบียนและสั่งงานได้แล้วทั้งสองตัว

สรุปสั้น ๆ: **ทุกอย่างพร้อมแล้ว เหลือแค่ปลุก runner บน PC1**

## ขั้นตอนที่ต้องทำ (ทำที่ PC1)

### ขั้นที่ 1 — เปิด PowerShell แบบ Administrator

กดปุ่ม Start → พิมพ์ `powershell` → คลิกขวา → **Run as administrator**

ถ้าหน้าต่างขึ้นถามว่าให้แก้เครื่องไหม → กด **Yes**

### ขั้นที่ 2 — รันคำสั่งเดียวนี้

คัดลอกทั้งบรรทัดนี้ไปวาง (วางแล้วกด Enter):

```powershell
powershell -ExecutionPolicy Bypass -Command "$u='https://raw.githubusercontent.com/aerismusic8-alt/aeris-drive-automation/ax-arena-roblox-game/AX_PC_CONTROL/pc1-bootstrap-once.ps1'; $p="$env:TEMP\pc1-bootstrap-once.ps1"; Invoke-WebRequest -Uri $u -OutFile $p -UseBasicParsing; & powershell.exe -NoProfile -ExecutionPolicy Bypass -File $p"
```

คำสั่งนี้ทำ 4 อย่าง เรียงตามนี้ (แต่ละอย่างมีประโยชน์ในตัวเอง):

1. **ปลุก runner** → ปลดล็อกงานที่ค้างคิวทั้งหมดทันที
2. **ติดตั้ง/เปิด winremote MCP** → ให้เอเจนต์คุมเดสก์ท็อปได้ ไม่ต้องมีคนนั่งกด
3. **เปิดทางเข้าสำรอง 2 ทาง** → Windows OpenSSH (จำกัดเฉพาะ tailnet) และ MCP ผ่าน tailnet
   สองทางนี้ **ไม่ต้องพึ่ง runner** ซึ่งสำคัญ เพราะ runner คือสิ่งที่พังไปแล้ว
4. **เขียนหลักฐาน** ว่าพบอะไรและแก้อะไร ลง `C:\AX-Runtime\evidence\pc1-bootstrap.json`

### ขั้นที่ 3 — ตอบคำถามที่จะขึ้น (อาจมี 1-2 ครั้ง)

สคริปต์จะ **บอกว่าต้องทำอะไร** ไม่ค้างเงียบ ๆ ถ้าเจอสองกรณีนี้:

| ถ้าเห็นข้อความ | ให้ทำ |
| --- | --- |
| `TAILSCALE_NOT_LOGGED_IN` แล้วมี URL ขึ้นมา | เปิด URL นั้นบนมือถือ (ที่ล็อกอินบัญชี tailnet เดียวกัน) แล้วกด Approve |
| `SERVE_FAILED` + แนะนำให้เปิด HTTPS | เปิด https://login.tailscale.com/admin/dns → เปิด **HTTPS Certificates** แล้วรันคำสั่งเดิมซ้ำ |

ถ้าไม่เห็นสองอันนี้ = ไม่ต้องทำอะไรเพิ่ม ปล่อยให้มันรันจนจบ

### ขั้นที่ 4 — บอกผลลัพธ์กลับมา

เมื่อสคริปต์จบ จะมีบรรทัด `RESULT` แล้วตามด้วยสรุป
ให้คัดลอก **3 บรรทัดนี้** ส่งมา:

```
TAILNET_IP=...
MCP_LOCAL=...
RESULT=...
```

ถ้าเห็น `TAILSCALE_MISSING_NO_WINGET` หรือ `TAILSCALE_INSTALL_FAILED`
ให้บอกด้วย เพราะแปลว่าเครื่องนี้ลง Tailscale อัตโนมัติไม่ได้
(กรณีนี้ยังใช้ทาง runner ได้อยู่ แต่จะไม่มีทางสำรอง)

## หลังขั้นที่ 2 เสร็จ — เอเจนต์จะทำต่อเอง

ไม่ต้องทำอะไรเพิ่ม เอเจนต์จะ:

1. เห็นว่างานที่ค้างคิวเริ่มวิ่งแล้ว
2. สั่ง `AX PC1 Desktop Control` เพื่อแคปจอ PC1 → ได้ไฟล์ PNG กลับมาดู
3. สั่งคำสั่งอื่น ๆ (เปิดโปรแกรม, รันสคริปต์, อ่านไฟล์) ผ่าน MCP
4. กลับไปแก้บั๊กเกมที่ค้างไว้ (เรียนสกิลไม่ได้, ของเริ่มต้นในกระเป๋าว่าง)

---

## ถ้าอยากคุมเองจากมือถือ (ทางเลือก ไม่บังคับ)

หลัง bootstrap เสร็จ เครื่องจะมีทางเข้าที่ไม่ต้องพึ่ง runner แล้ว:

| ทาง | เปิดจากมือถือยังไง | เหมาะกับ |
| --- | --- | --- |
| Tailscale + MCP | เปิด `https://<dns-name>/mcp` (ในเครือข่าย tailnet) | เอเจนต์สั่งงาน |
| RDP | แอป Microsoft Remote Desktop ต่อ `TAILNET_IP:3389` | นั่งดูจอเต็มรูปแบบ |
| MeshCentral | เปิดเว็บ MeshCentral ในเบราว์เซอร์มือถือ | ดูจอ + terminal |

หมายเหตุ: ห้ามใช้ Tailscale **Funnel** กับ MCP เพราะเปิดให้ทั้งอินเทอร์เน็ตเข้าได้
ใช้ **serve** เท่านั้น (สคริปต์ใช้ `serve` อยู่แล้ว)

---

## ทำไมออกแบบแบบนี้

**ทางที่สั้นที่สุดคือไม่ต้องมี Tailscale เลย** เพราะ MCP server ผูกกับ `127.0.0.1`
และ runner ก็อยู่บน PC1 เครื่องเดียวกัน จึงเรียกหากันได้ตรง ๆ
ไม่ต้อง forward port ไม่ต้องส่ง credential ให้ใคร

แต่ทางนั้น **ต้องมี runner ที่ยังไม่ตาย** ซึ่งตอนนี้ตายอยู่ จึงต้องปลุกก่อน
Tailscale จึงเป็น **ทางสำรอง** ที่ทำให้ครั้งต่อไปที่ runner ตาย จะไม่ตันอีก

สิ่งที่ยังต้องระวัง:

- `Shell` ของ MCP เป็น tier 3 (ปิดไว้โดยค่าเริ่มต้น) เพราะมันรันคำสั่งอะไรก็ได้บน PC1
  เปิดเท่าที่จำเป็น และไม่เปิดพอร์ตออกอินเทอร์เน็ตโดยไม่มี TLS + key
- auth key และค่า `AKATH_MESHCTRL_*` **ห้าม** commit ลง Git
  สคริปต์รายงานแค่ว่ามี credential หรือไม่ ไม่รายงานค่า
