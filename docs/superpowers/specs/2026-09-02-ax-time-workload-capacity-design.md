# AX Time, Workload & Capacity Control — Design

## Purpose
กำหนดมาตรฐานถาวรของบริษัท AX สำหรับการวัดเวลา ประสิทธิภาพ ปริมาณงาน ความสามารถรองรับงาน คอขวด และการคาดการณ์ภาระงาน

## Core Rule
เมื่อ K สั่งให้เพิ่มสิ่งใดเข้า “โครงสร้าง AX” ให้ถือเป็นข้อกำหนดระดับโครงสร้างบริษัททันที และต้องนำไปทำให้เกิดผลในระบบที่เกี่ยวข้องตามลำดับ โดยห้ามเปลี่ยนความหมายของกฎระหว่างการนำไปใช้

## Language Rule
AX ใช้ภาษาไทยเป็นหลักในการสื่อสารกับ K ใช้ภาษาอังกฤษเฉพาะศัพท์เทคนิคที่จำเป็น และต้องมีคำแปล/ความหมายภาษาไทยกำกับทุกครั้ง หากละเมิดหรือทำให้ความหมายคลาดเคลื่อน ต้องเข้าสู่ PCSEV และบันทึกเป็นประสบการณ์เพื่อป้องกันการเกิดซ้ำ

## Task Time Model
ทุกงานต้องมี Target Time (เวลาเป้าหมาย) และ Actual Time (เวลาที่ใช้จริง) แยกจากกัน โดยบันทึกเวลารับงาน, เวลาเริ่มจริง, หยุด/กลับมาทำต่อ, เวลาจบจริง และเวลาที่ใช้จริงตามหลักฐาน

## Workload Model
ระบบต้องติดตามงานที่กำลังทำ, งานรอคิว, อัตรางานเข้า, อัตรางานเสร็จ และงานค้างสะสม

## Capacity Model
ระบบต้องประเมินการใช้กำลังระบบ, กำลังที่เหลือ, Headroom (ความสามารถในการรับงานเพิ่ม), และ Maximum Sustainable Load (ปริมาณงานสูงสุดที่รองรับต่อเนื่องได้) จากข้อมูลจริง ไม่กำหนดจากการคาดเดา

## Bottleneck Model
ต้องระบุคอขวดจากหลักฐานจริง เช่น Agent/AI, Worker, Runner, Verification, External API, Queue หรือ Human Approval และแยกสาเหตุของความล่าช้าออกจากเวลาทำงานจริง

## Forecast
ระบบต้องสามารถคาดการณ์เวลาจบงาน/การเคลียร์คิว และแจ้งผลกระทบเมื่อมีงานใหม่เข้ามาเพิ่ม เช่น จุดที่เริ่มเกิดคอขวดและความเสี่ยงโหลดเกิน

## Executive Reporting
รายงานผู้บริหารต้องแสดง English Technical Metric พร้อมคำไทยกำกับ และมีข้อสรุปภาษาไทย เช่น สถานะ, ประสิทธิภาพ, โหลด, Capacity, คอขวด, ความเสี่ยง และเวลาคาดว่าจะเสร็จ

## Non-negotiable Evidence Rule
ห้ามถือ Batch Start เป็น Task Start หากยังไม่มีหลักฐานว่า Task นั้นเริ่มทำจริง และห้ามรายงานเวลาจริงจากการประมาณการ

## PCSEV Recovery Rule
หาก AX ไม่ปฏิบัติตามกฎนี้ ให้ทำ PCSEV: ปัญหา → สาเหตุ → วิธีแก้ → ดำเนินการ → ตรวจสอบ และบันทึกเหตุการณ์/สาเหตุ/วิธีป้องกันเป็นประสบการณ์ถาวร
