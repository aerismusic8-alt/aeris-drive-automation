# AX Control Hub — PC Installation Runbook

## Safety boundary

- Install and test on the Windows PC only.
- Do not expose the control port directly to the public Internet.
- Keep live financial execution disabled during validation.
- Do not place passwords, API keys, bootstrap secrets, or node secrets in Git.
- Existing AERIS Apps Script and AX Node Runner are not replaced by this installation.

## 1. Preflight

Run from the repository root in PowerShell:

```powershell
Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned
.\AX_CONTROL_HUB\PC_RUNTIME_CHECK.ps1
```

The preflight must fail closed if required runtime files, configuration, or local dependencies are missing.

## 2. Configure local secrets

Set credentials through the local OS/service secret mechanism selected by the runtime implementation. Do not add them to `config.example.json` or any repository file.

Required E2E environment variables:

```powershell
$env:AX_CONTROL_HUB_URL = 'http://127.0.0.1:8787'
$env:AX_CONTROL_HUB_USERNAME = '<local-admin-username>'
$env:AX_CONTROL_HUB_PASSWORD = '<local-admin-password>'
```

Use a strong unique password. Clear the environment variables after the test session when practical.

## 3. Start runtime

Start the Control Hub using the runtime-specific launcher documented by its implementation. Bind to loopback during initial validation.

Do not connect mobile/remote access until local E2E tests pass.

## 4. Execute E2E

```powershell
.\AX_CONTROL_HUB\AX_CONTROL_HUB_E2E.ps1
```

A non-zero exit code means the system is not verified.

## 5. Required evidence

Capture:

- exact commit SHA tested
- PC/runtime version
- test start/end timestamps generated by the runtime
- T1–T12 output
- M-A-CHECK response
- state/task source identifiers
- evidence correlation ID for any accepted command
- verification result

## 6. Only after local PASS

Proceed to authenticated mobile access through an HTTPS-secured tunnel or equivalent authenticated gateway. Never expose the raw local control port.
