## 06:20Z — two sessions hit the same problem (memory bloat); reconciled into one design

K asked (while rails were green): "ถ้าช่วงที่ว่าง ทำประชุมวางแผนเรื่องหน่วยความจำถาวร
ด้วย มันบวมขึ้นเรื่อย ๆ จะเป็นปัญหาใหญ่" — the persistent memory keeps growing; plan it.

**The measurement:** `MEMORY.md` was **133 KB / 1777 lines / 43 sections**, injected
into the model prompt **every session**, against its own declared ~6 KB cap — 22x over,
growing ~1.5 KB/commit. (Earlier it had been 128 KB; two sessions measured it.)

**The collision:** a *parallel AR session* had already been working the same problem
and merged its fix at 06:04Z — `8de638f` "fix(memory): cap the injected index at 6 KB
and guard it in CI" + `7c470d7`. My own commit (`62ba8a8`) then conflicted on rebase.
Two agents, one task, ~10 minutes apart. Resolved by **adopting the merged design and
folding my additive value into it**, rather than shipping a second, competing scheme
(two overlapping tools would be worse than either alone).

**The merged design (kept):** a three-tier scheme, enforced by `ops/memory_guard.py`
(`CAP_BYTES = 6144`, exit 1 over cap), pinned by `test_memory_guard`, and turned red by
`.github/workflows/ax-memory-guard.yml` (push on memory paths + a daily cron net).
- `MEMORY.md` = a 6 KB operating card (Rule #1 first, pointers), **injected**.
- `MEMORY-ARCHIVE.md` = every memory ever written, **moved-to, never deleted**.
- `YYYY-MM-DD.md` = session notes, never injected.

**My additive value (this commit):**
- `ops/memory_search.py` — the merged notes said the archive is "reachable by grep" but
  shipped no tool. This greps the card + archive + every daily log at once, grouped by
  section with line numbers (next step is `sed -n 'A,Bp' <file>`); `--titles` lists all
  587 sections. Stdlib only (no `rg` dependency), offline, free.
- `test_memory_guard` now also asserts a durable rule (`ฟรีเท่านั้น`) is actually
  **found** by that search — so "reachable" is proven, not assumed.
- AGENTS.md documents the search command.

**Lesson (durable, belongs in the card or a future card edit):** this account runs more
than one agent at once against one repo. Before starting a non-trivial change, `git
fetch` and check for a parallel commit — two sessions collided here. Reconcile into one
design; do not merge two overlapping mechanisms.

## Real-instrument CI fix (K: "เลิกใช้เลย หาโปรแกรมสร้างเสียงเหมือนจริง")

K rejected the General-MIDI SoundFont as fake (2026-11-09), and the beds the FB/TK
rails ship *are* the approved six moods — but the 24/7 rails run on `ubuntu-latest`,
which cannot build the sfizz sampler + gigabyte banks, so `soundfont.render_bed`
fell back to GM and published the exact timbre K refused. The gap was CI, not the
pod: `ambient_loop`/`sampler` already route to real instruments when the banks are
present, and no ffmpeg tone synth remains.

**Advisor panel (quorum PASS, duck + pollinations, 2026-11-12):** pre-render the
approved beds once and ship them as versioned release assets; make retrieval and
validation mandatory; **never keep GM as a silent fallback** — fail the workflow
loudly before publication. Matches the existing `media-938` pattern.

**Shipped (`35a6e358`, pushed with the vault workflow token):**
- 11 real-instrument beds rendered on the pod (sfizz + salamander/sso banks) and
  uploaded to `media-938` as `sampler1-*.wav` (~330 MB). Set = the 6 mood-clip keys
  (`calm-C warm-F sad-A hopeful-D mystic-G epic-F`) + the 5 `make_music` key-C beds.
- `soundfont.pulled_bed()` + a branch in `render_bed`: with no sampler, prefer the
  pulled bed and **tile it to the requested length** (a verbatim copy would shrink a
  210 s song bed to the 180 s loop unit).
- `AX_REQUIRE_REAL_INSTRUMENTS=1` makes a GM fallback raise (`_gm_fallback_or_raise`).
  Off by default so a dev pod still renders.
- `pull_media.group_of` routes `sampler1-*.wav` → `ambient/` **before** the generic
  `.wav → songs` rule; `publish_media.SOURCES` gains `("ambient", "sampler1-*.wav")`.
- Both rails pull `--only ambient` and set the require flag.
- `make_music`/`flow_song` record the real `source`, not a hardcoded
  `soundfont-fluidsynth`.
- `tests/run.py::test_real_instrument_guard` (11 checks) pins the guard, the
  pulled-bed preference, the pull/publish routing and the two workflows.
  Suite **1931 → 1932 passed / 0 failed** (one more after the origin rebase).

**Lesson:** a timbre change is not done when the pod renders it — it is done when
every *unattended* rail renders it. A runner that lacks the heavy dependency will
silently pick the fallback unless the code refuses to.
