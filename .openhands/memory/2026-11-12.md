## Session self-heal: the K-bottleneck in login is closed (2026-11-12, durable)

K's complaint: "มีช่องทางอื่นไหมที่ไม่ใช่ novnc มันจะล้างคุ๊กกี้ตลอด ล็อกอินบ่อยแบบนี้จะออโต้ได้ไง".
Root cause: the CI rails loaded a **frozen** Actions secret (`AERIS_STORAGE_STATE_B64`)
that nothing refreshed, while the durable vault already held the live cookie set.
A desktop sign-in never reached CI, so CI could only fail until K re-signed.

**The fix (all committed, `ops/`):**
- `ops/vault_session.py` — reads the vault cookie set as a Playwright storage_state,
  stores one back, writes a file for CI. No size cap (full session ≈ 682 KB; GitHub
  secret cap is 48 KB, so the secret could never hold it).
- `browser.connect` prefers the vault over the frozen secret (secret = fallback).
- crosspost / admin / dashboard workflows load the vault before the probe.
- `login_vault.save` + `save_storage_state` refresh the vault blob → **any pod
  sign-in heals CI** with no `gh secret set` and no K.
- `ops/session_guard.py` — checks every surface, revives what it can with no human,
  refreshes the vault, reports only what truly needs K. `--headless` = CI half.
- `.github/workflows/ax-session-heal.yml` — runs the heal every 6 h on the free
  runner. `bootstrap.py --heal` runs it after desktop bring-up.

**What is auto-revivable (verified live, no K):** Facebook (vaulted
`axsecrets:fb-password`) and **Flow Music** (Google SSO + `axsecrets:google-password`
— Flow has no password of its own). `AUTO_REVIVE = {"facebook", "flow"}`.
Still needs K: TikTok (device prompt), Shopee (slide puzzle) — reported, not guessed.

**Bugs found by running it (both fixed):**
- `login_vault._signed_in` required a positive marker AND no negative one, but Flow's
  probe is all-negative (`!Log in`). Flow could therefore **never** report signed-in —
  it read as dead while the studio was open, which would keep paging K for a working
  login. An all-negative probe now reports signed-in when its markers are gone.
- `fb_relogin` checked only the `c_user` cookie, so it said "already signed in" for a
  session Facebook had actually rejected. It now verifies the **page**.

**Proof (2026-11-12 21:1x Thai):** a fresh crosspost run restored the vault session
and **posted a real Facebook Reel** (`facebook 18/152 posted`, `posted -> /reel/1773469567470509/`)
with no K. The prior run (old workflow) failed with "132 post(s) pending but the
session is signed out" and pinged K — that is the loop that is now closed.

**Not touched / still open:** the 5 failing content-catalog tests (themes/tempo/mood
span) are pre-existing and unrelated — they want more songs in the catalog, not code.
