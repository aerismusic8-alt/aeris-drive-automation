## 06:20Z — two sessions hit the same problem (memory bloat); reconciled into one design

K asked (while rails were green): "ถ้าช่วงที่ว่าง ทำประชุมวางแผนเรื่องหน่วยความจำถาวร

**The measurement:** `MEMORY.md` was **133 KB / 1777 lines / 43 sections**, injected
into the model prompt **every session**, against its own declared ~6 KB cap — 22x over,
growing ~1.5 KB/commit. (Earlier it had been 128 KB; two sessions measured it.)

**The collision:** a *parallel AR session* had already been working the same problem
and merged its fix at 06:04Z — `8de638f` "fix(memory): cap the injected index at 6 KB
and guard it in CI" + `7c470d7`. My own commit (`62ba8a8`) then conflicted on rebase.
Two agents, one task, ~10 minutes apart. Resolved by **adopting the merged design and
folding my additive value into it**, rather than shipping a second, competing scheme
(two overlapping tools would be worse than either alone).

**The merged design (kept):** a three-tier scheme, enforced by `ops/memory_guard.py`
(`CAP_BYTES = 6144`, exit 1 over cap), pinned by `test_memory_guard`, and turned red by
`.github/workflows/ax-memory-guard.yml` (push on memory paths + a daily cron net).
- `MEMORY.md` = a 6 KB operating card (Rule #1 first, pointers), **injected**.
- `MEMORY-ARCHIVE.md` = every memory ever written, **moved-to, never deleted**.
- `YYYY-MM-DD.md` = session notes, never injected.

**My additive value (this commit):**
- `ops/memory_search.py` — the merged notes said the archive is "reachable by grep" but
  shipped no tool. This greps the card + archive + every daily log at once, grouped by
  section with line numbers (next step is `sed -n 'A,Bp' <file>`); `--titles` lists all
  587 sections. Stdlib only (no `rg` dependency), offline, free.
- `test_memory_guard` now also asserts a durable rule (`ฟรีเท่านั้น`) is actually
  **found** by that search — so "reachable" is proven, not assumed.
- AGENTS.md documents the search command.

**Lesson (durable, belongs in the card or a future card edit):** this account runs more
than one agent at once against one repo. Before starting a non-trivial change, `git
fetch` and check for a parallel commit — two sessions collided here. Reconcile into one
design; do not merge two overlapping mechanisms.

  Suite **1931 → 1932 passed / 0 failed** (one more after the origin rebase).

**Lesson:** a timbre change is not done when the pod renders it — it is done when

## 11:00Z — the daily verifier was silently broken since the channel passed 50 videos

While updating aeris938-2 I read the four surfaces live and ran the verify loop
(`live_audit.py`). It printed *"quota spent, retry next round"* — but the real
error was `videos.list HTTP 400: invalid filter parameter`. Root cause: the channel
now has **62 uploads**, and `videos.list` accepts **at most 50 ids per call**;
`read_live()` joined every id into one call. The code caught any non-200 as
`QuotaError`, so a hard bug was reported as a routine, self-healing quota state —
invisible, and exactly when the channel crossed the threshold that made verification
matter. The single most important rail was blind and said it was fine.

Advisor panel (quorum PASS, duck + pollinations) converged on the fix I had already
prepared: chunk + one shared helper + stop mislabeling. Shipped:

- `ops/yt_auth.get_videos(token, ids, part)` — the one place that knows the 50-id
  limit; chunks internally, returns `(status, items)` so a caller can tell a real
  400 (a bug) from a 403 (quota). Routed `live_audit.py`, `apply_live_metadata.py`,
  `apply_live_titles.py` through it (`yt_list_videos.py`, `yt_delete.py`,
  `yt_video_status.py` already chunked).
- `live_audit.read_live()` now raises `RuntimeError` (rail red) on a non-quota error
  and `QuotaError` only on 403. Removed the dashboard rail's `|| echo "...skipped"`
  that swallowed the exit code — the same `|| echo` pattern that hid the failure.
- `test_surfaces.py`: 62 ids → chunks `[50, 12]`; a 400 raises RuntimeError, a 403
  raises QuotaError. 35 pass.
- **Repaired the product:** the audit found 28 live videos with no subscribe ask
  (31 misses). `live_audit.py --repair` added the CTA to all of them (HTTP 200);
  re-audit → "✅ ผ่านทุกข้อ" over 62 videos. The verification rail had never reached
  this repair because it never got past the 400.

Two more pod/recycle findings, same class as the earlier numpy gap:
- `duck` (advisor seat) failed `ModuleNotFoundError: No module named 'websocket'` —
  `websocket-client` is declared in requirements.txt but was not installed, so the

- The suite then died on `FileNotFoundError: no SoundFont` — fluidsynth +

## Evidence gate: never decide on missing/stale data (2026-11-12)
Full detail behind the MEMORY.md "Never decide on missing/stale data" line.

- **Trigger.** The four-surface loop reported ฿0 with a "reach" blocker every day
  for ~10 days. Advisor panel (`ops/consult.py`, duck + pollinations, quorum PASS)
  found the reports themselves were the fault: three bugs of one class — a
  measurement that failed silently.
- **Bug 1 (root).** `aeris938-2/scripts/report.py` appends a `history.jsonl` row
  even when the cloud desktop is down and every dashboard field is null (e.g.
  `2026-11-12T10:54:12Z`). `goal_watch` read the nulls as "flat" and named
  "reach" — a guess dressed as a finding.
- **Bug 2.** `live_audit.py` built one `videos.list` call for all 62 uploads; the
  API caps at 50, so it 400'd and the run was silently blind. Fixed earlier the
  same day (`fix(yt): chunk videos.list past 50 ids`, 3c24ac9).
- **Bug 3.** `|| echo "...skipped"` in four workflows turned a real failure into a
  green run; `engagement.py` cached an unreadable TikTok page as permanently
  unreadable (`None` written to `engagement-cache.json`).
- **Panel verdict.** Do the shared "valid evidence" gate first, as a small shared
  module, not a special case; every number carries value + source + observed-at;
  consumers accept only when valid AND fresh; roll out reversibly.
- **Shipped.**
  - `aeris938-2/scripts/evidence.py` — status fresh|stale|unknown; `usable()` only
    when fresh; `FRESH_MINUTES = 120` (above any within-job delay, below the 6h
    dashboard cadence so a missed tick is still caught).
  - `goal_watch.diagnose()` names the constraint **`data`** (never "reach") when
    the newest reading is missing/stale, prints which surfaces are blind;
    `--assert-fresh` exits non-zero (the dashboard rail's gate).
  - `experiment_loop.evaluate()` returns INCONCLUSIVE on missing/stale evidence,
    keyed to the metric the experiment depends on (`yt_subs`; Shopee for an
    offer/income test). `decide()` **holds** (action "wait") when constraint is
    `data` — it neither closes nor opens a test on numbers it cannot read.
  - Workflows: no `|| echo` on the measurement chain; the live audit is its own
    step; a new freshness-gate step; a dead ntfy alert and a skipped upload now
    surface as `::error` / `::warning`. `engagement.py` retries an unreadable page
    next run instead of caching `None`.
- **Tests.** `aeris938-2` 40 passed (5 new); `music938-1` 1774 passed, 5
