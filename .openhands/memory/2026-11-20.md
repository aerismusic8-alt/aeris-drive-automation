### Correction (2026-11-20, later): the gate is per model *and* resolution

`model list --type video` reports `vipRequired: false` for **every** model, and
that field is not the gate. Creating a node is a separate check from running it:

| Call | Result |
| --- | --- |
| `node create video --model seedance_2.0_mini` (480P/540P/720P) | `service.10000 … requires VIP membership` |
| `node create video --model ltx_2.5_fast --resolution 720P` | node created OK |
| `node create video --model pixverse_v5 --resolution 720P` | node created OK |
| `node run` on either created node | `cli.node_run_unknown`, then `node show` still `status: empty`, 0 resources |

So a created node proves nothing; the run is what the gate rejects. Also: the CLI
silently rewrites 480P/540P up to **720P** (`generation.parameters_adjusted`), so
"try a lower resolution to dodge VIP" does not exist — 720P is the floor.
Conclusion unchanged: **no video on this account**, images only.

## The lanes were reworking old songs (K, 2026-11-20)

K after the 53-clip deletion: the deleted clips were not a new direction, and
neither was the way new ones were made — the work "ค้างในระบบตั้งนานแล้ว" and the
lane "ก็ไปวนเอาของเก่ามาทำ". Two separate causes, both measured, not guessed.

**1. `ops/clip_lane.py` ranked every song alike.** The rail does
`--list-songs | shuf -n 1`, and the list was every publishable song, so a song
with 7 clips was as likely as one with none. Measured on `media-938`: 22 songs
had 5-7 clips each, 10 had never been touched.

- `_song_id()` folds the two mixes into one song (`song-<id>`, `karaoke-<id>`);
  keying by filename treated one song as two.
- `_used_ids()` marks a song used when any `.mp4` asset name *contains* its id
  (`concert-15-x.mp4`, `short-karaoke-15-x.mp4`, `bank-song-15-x-<query>.mp4`).
  Prefix-stripping never lined up because the ids already carry a prefix.
- `unused_first()` offers un-clipped songs, and falls back to the whole
  catalogue once every song has one — a picker that can empty itself starves.
- `available_songs()` uses the **release** as the catalogue and only adds local
  files absent from it. The old "local first, else release" meant a pod with one
  cached mp3 offered exactly one song.

**No ledger knows this.** `crosspost-state.json` named none of the 22 used
songs; only the asset filenames are truthful.

**2. `produce_loop.py` built its used-set from the queue log alone.** The log
named 29 titles while `lyrics/` held 47 → 23 finished songs were invisible and
their themes were picked again (`วันธรรมดาที่พิเศษ` 5×, `ลุกขึ้นแล้วไป` 4×).

- `lyric_titles()` reads `# TITLE:` from `lyrics/*.txt`.
- `taken_titles()` = `attempted_titles(q) | lyric_titles()`, used at both pick
  sites. `attempted_titles()` stays log-only **on purpose**: an existing test
  pins that one transient draft failure is still retried, and folding the disk
  titles into it silently removed that guarantee (caught by the suite).

**Also fixed:** `ops/genart.py` wrote a manifest row for a probe render into
`/tmp`, so the tracked manifest claimed a work whose pixels lived in a temp dir
and `has its pixels somewhere` failed for everyone. Only art inside `ART` is
recorded now.

## The compass session (2026-11-20, continued)

**K's problem:** "แนวเพลงสร้างคลิป ไม่มี เข็มทิศหายแบบนี้ก็หลงทางสิ" — the direction

1. Three render lanes (`make_short`, `make_surreal_short`, `make_concert_short`)

   `ax-clip-lane.yml` rendered, stored to `media-938`, and stopped. No bank clip

**The fix is one file, `ops/compass.py`.** It is a registry of lanes: for each,
which script renders it, whether it is a product or a tool, what audio it needs,
which `clip_standard` profile it must hit, where it writes, and which rail runs
it. Everything else now asks it. `--check` reports 72 invariants and must be
clean; `test_compass_is_the_one_direction` pins it in the suite.

**The trap that cost the most.** The first version of that test asserted the
string `"compass"` appeared in each lane's source. Injecting the old glob back
into `make_short.py` did **not** fail it, because the comment above the code
still mentioned the compass. A test that a comment can satisfy guards nothing —
this is the same class of bug AGENTS.md records for `Skills.hotbar` ("assert the
result is non-empty, not just well-formed"). It now asserts `compass.songs(`
specifically, and the same injected regression turns the suite red.

**The bank rail.** New `.github/workflows/ax-bank-publish.yml`, every 4 h at
`:25` (offset from the clip lane's `:10 */3`). It fetches the mp4s from
`media-938` because `library/bank/` is gitignored, publishes through
