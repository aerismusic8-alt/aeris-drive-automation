### Capability discovery — the old "no workflow scope" rule is half wrong
- **`workflow_dispatch` works** with `AX_GH_TOKEN` (classic PAT, scopes
  `gist, read:org, repo`). Verified: dispatched the release and watchdog runs.
- **git push of a `.github/workflows/*.yml` is rejected** ("refusing to allow an
  OAuth App to create or update workflow ... without `workflow` scope").
- **Contents API PUT of a workflow is also rejected** — 403 for an existing file,
  404 for a new one. My first probe returned 200 only because it re-sent the
  *identical* blob; that is a no-op, not a write. Do not trust that 200.
- **Consequence:** AR can *run* and *read* workflows but cannot *edit* them.
  Any new/changed workflow needs K or PC1. Ship reliability logic as **plain
  Python under `ops/` or `plugins/`** instead, which a normal push carries.

  recently; flags a dropped cron and a rail whose cron **never fired** (only

  hourly `ax-rail-watchdog.yml` already runs — no workflow edit needed. Verified

- It resolves its token from `GITHUB_TOKEN`/`AX_GH_TOKEN` or, failing that, the

### GitHub cron delivery is best-effort and often badly delayed
- Measured: the hourly `ax-roblox-live-state` (cron `0 * * * *`) ran at 02:01
  then 19:15 — ~17h apart; watchdog ran 23:53 then 06:48. Interval crons are
