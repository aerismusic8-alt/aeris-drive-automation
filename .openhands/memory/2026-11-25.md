## Three scheduled rails were red on 11-24, each for a real reason

Checked the run history instead of assuming: 3 × AX Clip Lane, 1 × AX Music MV,
1 × AX Bank Publish. All three failures reproduced locally.

1. **AX Clip Lane** (`44989698646`, `45404537053`, `45513358571`) — every one died at
   the same line: `songs: could not list the release (HTTPError)`. `--list-songs`
   listed the `media-938` release **unauthenticated**; the anonymous GitHub pool is
   60 req/hour **per IP**, and a hosted runner's IP is shared. Fix: pass
   `AX_GH_TOKEN` in the workflow env, and retry 429/5xx with backoff instead of
   dying on the first response.
   Verified by dispatch: run `45529926396` green — picked `song-55-yang-khit-thueng`,
   `PASSED the floor`, durable copy `clip-20261125T0204-bank-song-55-...mp4`.

2. **AX Music MV** — the picture-ledger commit pushed without rebasing. A 4K render
   runs 20–40 min, so the dashboard committed to `main` first and the push was
   rejected **after** the MV was already on the release (a red run for a successful
   job). Every other ledger commit rebases; this rail was the one that did not.
   Fix: `git pull --rebase --autostash` before the push.

3. **AX Bank Publish** — two defects in one rail:
   - `gh release download --pattern '*.mp4'` pulled **every** mp4 (162 assets:
     Shorts, MVs, concerts, surreal) into `library/bank` and reported 162 pending
     bank clips where the release holds **17**. Fix: `--pattern 'bank-*.mp4'`.
   - the genre gate fails closed without the song master, and a runner has none, so
     the rail would have blocked. Fix: `_ensure_master()` restores just the one
     master through `pull_media.fetch` (5 MB, not 695 MB of audio).
   Verified locally: restored `song-09-...mp3` then `GENRE OK ... genre 'pop'`.

Each fix is pinned by a source check in `music938-1/tests/run.py`
(`test_clip_lane_is_its_own_job`, `test_render_workflow_deps`).

## The experiment loop had been answering "exhausted" for a real bottleneck

`experiment-state.json` said `{"constraint": "retention", "action": "exhausted"}`.
The cause was not a used-up library — the library had **no `retention` key at all**
(only reach/conversion/offer/income). `goal_watch.diagnose()` can return
`retention` and `mixed`, so a real bottleneck produced **no experiment for as long
as it stayed the bottleneck**. K's rule is that a flat day must produce a new
method; the loop had silently stopped.

- Added 3 retention hypotheses (continuous long-form mix, playlist hand-off,
  8-hour sleep loop) and 2 mixed ones (follow ask in every format, repost the
  winner on every channel), each with one variable, a peer, a metric, a guardrail.
- A retention verdict now reads **watch-hours per 1,000 views**, not subscribers:
  total hours rise with views, so a reach spike would masquerade as retention.
  `HOURS_MAX_AGE_MINUTES` is 7 days because the Studio scrape is written by hand on
  K's desktop and the number is a 28-day rolling total — the 2-hour window would
  make every retention verdict permanently inconclusive.
- `report.flatten()` now records `yt_hours` + `yt_hours_at` (from the newest
  `studio-*.json`, dated by file name), and `goal_watch.studio_hours()` delegates to
  `report.studio_hours()` so there is one reader.
- `test_experiment_loop_answers_every_diagnosis` pins that every constraint the
  judge can name has a method, and that the retention verdict reads hours.
