## Dispatching an automation by hand (undocumented endpoint)

The API path is not obvious and guessing costs time. To run an OpenHands
automation immediately:

```bash
curl -s -X POST -H "Authorization: Bearer $OPENHANDS_API_KEY" \
  https://app.all-hands.dev/api/automation/v1/<automation_id>/dispatch -d '{}'
# -> 201 {"id": "<run id>", ...}
```

`POST /runs` is **405** (that path is list-only). `/run`, `/trigger` and
`/runs/trigger` are **404**. `/dispatch` is the one that works.

Run state: `GET /api/automation/v1/<id>/runs?limit=N` →
`status`, `error_detail`, `current_phase`, `timeout_at`, `sandbox_id`. There is
**no** `/runs/<run_id>` detail endpoint (404) — read the list.

**A run can hang in `current_phase: "Starting automation"` until `timeout_at`,
with `conversation_id: null`.** That is the "Sandbox not available" cold-start
flake, not our code: the sandbox id is allocated but never boots. Retrying is the
only fix. Do not chase it in the plugin.

## The music-release automation never ran — two bugs, both found (AR, autonomous)

K: "บริหารงานและตัดสินใจแทนk". Chasing it found the real reason the daily release
had not happened, and it was not the platform.

**Bug 1 — the plugin ran in the wrong directory.** A run failed with
`can't open file '.../plugins/music-release/music938-1/scripts/daily_release.py'`.
The automation fetches **only the plugin directory**, so `AUTOMATION_PLUGIN_ROOT`

**Bug 2 — a relative `--root` doubled the path.** `Path(".")` resolved against
the driver's cwd produced `music938-1/music938-1/scripts/release.py`. Fix:
`Path(args.root).resolve()` before use. The progress file also went to the repo
root; it now goes to a temp dir.

Verified locally end to end (both bugs fixed, the full path runs and reports the
quota): `python3 plugins/music-release/scripts/main.py`.

**The cascade was self-inflicted, and this is the trap to avoid:** the platform
allows **20 sandboxes per day**. Each retry of a cold-start flake burns one, and
after the 20th the next dispatch is `SKIPPED — "Daily sandbox limit of 20
reached"`, which looks like a new bug and is not. **Retry a flaky run at most
once or twice, then leave it to the cron.** A run stuck in `current_phase:
"Starting automation"` with `conversation_id: null` is a platform cold-start
flake; do not dispatch again for it.
