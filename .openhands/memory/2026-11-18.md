## Session (2026-11-18 ~02:00 UTC / 09:00 Thai): the vault was never gone

K asked "อัพเดทงานล่าสุดถึงไหนแล้ว" after AR had claimed FB had "no token".

**Root cause found.** `ax_vault.ensure_anchor()` listed automations
(`GET /api/automation/v1`) to discover the anchor id. That endpoint 401s in an
interactive sandbox while the KV read works with the same key, so every caller
(`fb_graph.page_token`, `ar_identity`, `login_vault`, `k_free_status`) silently got
`""` and reported a *missing token / signed-out surface* — a false "the vault is
gone". Fixed to read the id from the `AX_VAULT_BOOTSTRAP` secret first
(`bootstrap_anchor()`: env, then `ax_secrets`), listing only as fallback.
Pinned by `music938-1/tests/run.py::test_vault_key_fallback`.

**The token was there all along.** With the anchor resolved, `axsecrets:fb-page-token`
reads (len 205) and `axsecrets:gh-workflow-token` reads as a dict with scopes
`repo,workflow`. So K was right: FB_PAGE_TOKEN is provisioned. The earlier "no token"
was AR's bug, not a missing credential.

**Sandbox quirk that cost time.** A registered secret is injected into the env only
when the *command text names the key*. `python3 ops/apply_fb_brand.py` alone → vault
closed ("no token configured"); naming `OPENHANDS_API_KEY`/`AX_VAULT_BOOTSTRAP` in the
command → vault opens, token read, Graph called.

**Why the Graph call still fails.** `API access blocked` (OAuthException code 200,
subcode 5258005) on *every* call including `GET /me`. Matches a known Meta state: the
**app is "Restricted"** because "all admins must confirm their developer portal
accounts". Required action: app admin opens developers.facebook.com/apps and completes
the confirmation steps. Owner-only → hand to K. (research: developers.facebook.com
community thread 1615319960638311.)

### FB block is APP-level, not System-User-level (confirmed 2026-11-18)
K created a System User `ax-poster` (id 61596192547961, Employee access level). The
block did **not** clear: the old token (vault `axsecrets:fb-page-token`, prefix
`EAAUrpQnz050…`) and a call to the new System User id both still return
`API access blocked` 5258005. Meta's own forum (community thread 27013639341611119)
shows the identical case: a brand-new System User with full asset control still gets
5258005 on the basic `GET /me`. So the restriction lives on the **app**, and creating a
System User cannot clear it. Two separate things are required:
1. Clear the app restriction (the real 5258005 fix): developers.facebook.com/apps →
   the app → act on the red "API access restricted" banner, and ensure **all app
   admins** have confirmed their developer-portal accounts.
2. A **fresh token generated from ax-poster** — the vault token is still the old one;
   a new System User needs its own token generated. Also prefer role **Admin** over
   Employee so the token can carry the full scope set.
