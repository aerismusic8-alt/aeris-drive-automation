## The clip floor gate needs its own deps on every rail (2026-11-18)

K asked to update the latest work; checking the **rail run history** (not
`heartbeat.json`) showed the *revenue* rail red: `ax-music-release.yml` failed
twice in a row (2026-11-17T17:33Z, 2026-11-18T02:20Z), step "Release the day's
batch".

Root cause, read from the run log: the clip floor gate (`ops/clip_standard.py`,
added 2026-11-17 in `7d69595`) is **fail-closed** — `yt_publish.py` refuses to
upload when it cannot measure the file — and it measures with
`ffprobe` + `imageio-ffmpeg` + `numpy` + `Pillow`. `ax-music-release.yml` never
installed any of them, so every clip read as `readable file (No module named
'imageio_ffmpeg')` → **CLIP STANDARD: below the floor → refusing to upload**. The
gate was right; the runner was under-provisioned. Nothing was published.

Scope: **two** rails run a gated upload path with no ffmpeg —
`ax-music-release.yml` (release/replace/thumbnail repair) and
`ax-music-crosspost.yml` (its `--post` path calls `assert_ok` in
`fb_graph`/`tiktok_api` and in the browser composers). The render rails only
`--merge-queue`/`--promote-*`, which touch no clip, so they are fine; the others
(compilation, produce, trivia, …) already install ffmpeg.

Fix: added an "Install ffmpeg and the clip/thumbnail gate deps" step (ffmpeg via
apt when absent; `pip install imageio-ffmpeg numpy Pillow`) to both workflows,
before any upload step. Regression test added to
`music938-1/tests/run.py::test_clip_standard_is_a_floor`: it scans every workflow
that invokes a gated upload path (`release|yt_publish|trivia_publish|
upload_compilation|replace_video|daily_release`, or `crosspost.py … --post`) and
fails unless that workflow installs ffmpeg + numpy + Pillow. Verified it fails on
the pre-fix release workflow.

Lesson: a fail-closed gate turns a *missing dependency* into a **quality
rejection**, which reads as "the clip is bad" instead of "the runner can't read
it". Any new gate primitive must ship with its own install step on every rail it
gates, and a test that pins that wiring.

Sandbox note: this pod has no ffmpeg/ffprobe on PATH. `/workspace/ax-tools/ffmpeg/
ffmpeg-master-latest-linux64-gpl/bin` (durable) holds both — put it on `PATH`
before running the clip suite. `pip install imageio-ffmpeg numpy Pillow pytest`
completes the Python side. With that, 568 checks pass and the suite stops only at
the known SoundFont gap.

## Music generation — what the pipeline actually uses (answered 2026-11-18)

K asked: "โปรแกรมสร้างเพลงที่จริงก็เยอะนะ ที่เราใช้อยู่พอใช่ไหม" (there are many real
song generators; is what we use enough?).

Inventory read from the repo:

- **Flow Music** (`music938-1/scripts/flow_song.py`) is the ONE real singing
  model. Login-only Google web app; driven on the cloud desktop. A generated song
  is served from a public GCS bucket (`producer-app-public/clips/<id>.m4a`) and
  the driver pulls the audio without a download click. **Its free credits are the
  real bottleneck** — `_out_of_credits()` maps "out of credits" to `RateLimited`,
  and the code comments say a few renders/day. Every song that ships with vocals
  is a Flow render.
- **`make_song.py`** is the fallback *instrumental bed* — syllable-by-syllable
  Piper TTS pitch-shifted onto notes + ffmpeg backing. K **rejected** it as a
  vocal source ("that is not singing", per flow_song.py's own header), so it is
  the bed-only lane. `produce_loop.py` used to default to the bed and shipped
  songs 25/26 as mono beds; K caught it by listening. Flow is now the default,
  `--no-flow` opts out.
- **`forge_song.py`** is the multi-AI lyric/melody *filter* (Gemini drafts ->
  critique -> only then spend a Flow credit). Not a generator.
- **sfizz** sampler + `AX_REQUIRE_REAL_INSTRUMENTS=1` = real-instrument sound
  banks (not a generator).

Verdict: Flow Music is the only real singing source and it is free — so it fits
Rule #1 and is the right tool. The constraint is credits, not choice. Genuinely
free alternatives worth knowing (NOT wired in): ACE-Step (Apache-2.0, local,
commercial-use OK) and YuE (open weights, lyrics->full song with vocals, heavier
GPU). Both would need a real GPU box; the sandbox has none, so they are a note,
not a plan.
