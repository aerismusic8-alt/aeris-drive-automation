## Growth loop fix — "follow as the Page" (2026-11-06)

The `ax-growth` automation had been failing every run for a real reason, not a
flake: `outreach._acting_as_page()` tested `"จัดการเพจ" in body`, but that string
is also the *personal* profile's left-rail entry for the pages it manages, so the
check was a **false positive**. The switch was skipped, and the two follows the
run reported landed on K's personal profile (the Page's "กำลังติดตาม" stayed 30).
The run history then showed FAILED only because `fire_callback` returned 401.

Fix (verified live, not just by reading the DOM):
- `_acting_as_page()` now rejects the "สลับไปใช้เพจ … เพื่อดำเนินการเพิ่มเติม"
  banner and requires the Page-only "แก้ไขรูปภาพหน้าปก" anchor.
- `_switch_to_page()` uses the proven three-click sequence from
  `profile_setup._fb_switch_to_page` (profile switcher → "สลับ" in the menu →
  "ใช้เพจ" in the welcome dialog). A single banner click does **not** switch: FB
  just re-renders the visitor view.
- `_page_following_count()` reads the `sk=following` tab, because the bare
  profile URL sometimes renders the visitor view and returns None.
- Result: `31 -> 33 (+2)` after the fix; the same run before the fix left it at 30.

Advisors (duck + duck-claude + duck-oss, 3/3; chatgpt/gemini tabs were not open
so they did not answer): do **not** trust a text match or "banner absent" as proof
of identity; switch through FB's own control, **re-verify after navigation**, and
fail closed. That is what the fix does. They also would not bless a follow loop at
all — the risk is misattribution to the personal profile, which is exactly the bug.
