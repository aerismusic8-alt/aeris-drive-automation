### Durable traps found on the way

- **`music938-1/work/affiliate-products.json` was gitignored and had never been
  committed.** A fresh pod therefore had no cards: `make_affiliate_short` could
  not run, and `tests/run.py` died with `IndexError` on an empty product list —
  which reads as "the suite is broken", not "a file is missing". It is now
  tracked, with the same rationale as the other `work/` state files.
  **Recovery route for a lost work file:** the conversation event log under
  `/workspace/conversations/<id>/events/event-*.json` still holds the
  `file_editor` `create` payload (and terminal `cat` observations). `grep` the
  event files for a stable string from the file, pull the JSON out of
  `observation.content[0].text`, brace-match it. That is how the 5 cards came
  back.
- **`main` is protected by a ruleset.** A direct `git push` to `main` is rejected
  ("fatal error in commit_refs_rules"). The route is: push a branch, then create
  and merge a PR through the REST API.
- **`scripts/gh-app-token.mjs` finds no credentials in a fresh pod** — the App
  key lived on the ephemeral overlay. The working write path is the classic PAT
  in `AX_GH_TOKEN` (`repo,workflow`): use it in the push URL and as the API
  `Authorization: token …` header. The sandbox `GITHUB_TOKEN` is read-only (403).
- **`ffmpeg`/`ffprobe` are at `/workspace/ax-tools/bin` (symlinks to
  `/workspace/ax-tools/ffmpeg/...`).** Add that dir to `PATH` or several tests
  fail (`compile_album.duration` → `FileNotFoundError: ffprobe`), which looks
  like a code bug but is just a missing binary.
- **YouTube quota is 6 uploads per Pacific day.** `release-state.json` showed
  6/6 spent on 2026-11-05, so the affiliate clips go out at the next 07:00 UTC
  run (`ax-music-release.yml`, cron `0 7,13,19 * * *`). A local `--dry-run` says
  so plainly ("today's quota is spent: 6/6").
- **TikTok: a profile page renders logged-out, but posting/editing needs a live
  session.** `@aeris.music4` reads fine (1 follower, 0 likes, bio visible) while
  `/tiktokstudio/upload` bounces to `/login` — so "the page loads" is not
  "signed in". The bio's Shopee link is still missing; that needs K's login.

## Five advisors + click path (this session, PR #55 → merge 338608a9)

- **K raised the advisor panel from 3 to 5** ("เพิ่มเป็น 5 ที่ปรึกษาเลยในทุกงาน").
  `ops/consult.py` `VENDORS` is now five: `chatgpt`, `gemini`, and three Duck.ai
  models — `duck` (default), `duck-claude` (Claude Haiku 5.5), `duck-oss`
  (gpt-oss 120B) — via `duck_ask.ask(model=...)`. `MIN_ADVISORS = 3` is the
  quorum: five are asked, three must answer, so one signed-out web app does not
  block the rail but a single reply can never pass for a panel. The gate
  (`consulted()`) counts `ok` answers, not just "any".
- **Duck.ai exposes a model picker** ("Switch model" button) with GPT-5.4 mini,
  Claude Haiku 5.5, Mistral Small 4, gpt-oss 120B, and PRO/PLUS tiers. Selecting
  one is `_pick_model()`; it is what gives three free advisors from one page.
- **The 5/5 panel verdict** on the quota brief: affiliate-first, **2 product : 4
  replacement per day for 3 days**, and *the reserve must be real* or the
  backlog eats the day. ChatGPT even argued 4 product : 2 replacement. Every
  one of the five flagged that a Short's description link may not be clickable.
- **The reserve is real now.** `release.AFFILIATE_RESERVE = 2`; `replace_video.py`
  refuses to upload once `used >= UPLOADS_PER_DAY - reserve`, where
  `reserve = min(2, affiliate_pending())` — so it holds slots only while a card
  is pending and releases them once every card is live. `pending_replacements.py`
  calls `replace_video.py`, so the guard is on the real path.
- **The click path is a pinned comment, not the description.** `studio_web.py`
  `short_pin_targets()` now returns `(video_id, text, marker)` for both a song
  Short (youtu.be link) and a product Short (tracked Shopee link + affiliate
  disclosure). A pinned comment's link *is* tappable where a description link may
  not be. The channel About description's old untracked `th.shp.ee/6hv2uk89` was
  swapped for the tracked `s.shopee.co.th/8pn3G4alfI` (sub_id1=youtube) via a
  `channels.update` (brandingSettings) — verified live.
- **`brandingSettings.channel.description` is writable through the API** with
  `channels.update part=brandingSettings`, so the About page is a scriptable
  click surface (unlike the profile *links* section, which is not in the API).
