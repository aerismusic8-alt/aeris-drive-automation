## 00:50Z (11-12) — "does it walk on its own?" audit found 3 live rail failures, fixed
K asked whether the loop reaches the goal by itself. Checked the real state instead of
trusting the heartbeat file (last written 2026-11-03 — itself a sign of drift). Read the
last run of every workflow through the API. Three rails were red:
- **AX Rail Watchdog** (hourly, the self-healing watcher) — failed 2026-11-11T21:59Z.
  Root cause: it imports `k_free_status.audit()`, whose `_vault_has()` called
  `ax_vault.ensure_anchor()` inside `except Exception`. On a GitHub runner the API
  rejects the call and `ensure_anchor` raises **SystemExit** (a BaseException), which
  `except Exception` does not catch — so the job died with exit 1, and because the
  workflow uses `bash -e` the whole run was lost. `ops/fb_graph.py` already carried this
  exact lesson ("SystemExit ... a plain `except Exception` misses it"); the fix was never
  propagated to `k_free_status.py`. Changed the guard to `except BaseException` there.
  Simulated a CI run (`env -u OPENHANDS_API_KEY`) → the watchdog now exits 0.
- **AX Music Concert Render** — `ModuleNotFoundError: No module named 'numpy'`. The
  workflow installed ffmpeg but not numpy; `make_concert_short -> concert -> make_song`
  imports numpy at module load. Added `pip install numpy`.
- **AX Music Karaoke Render** — died inside `sudo apt-get install ffmpeg` when
  `security.ubuntu.com` briefly failed to resolve (runner retried ~1h). ffmpeg ships on
  ubuntu-latest, so the apt call was a needless single point of failure. Both render
  workflows now `command -v ffmpeg` first and only apt-install when absent.
Regression guards: extended the vault-guard test to include `k_free_status.py`, and added
`test_render_workflow_deps()` (concert installs numpy; both render rails guard the ffmpeg
install). Suite: **1756 passed** (was 1752; +4), same 5 pre-existing asset-dependent
failures (themed compilations need built songs).
Also: this pod was missing its declared deps (numpy/pythainlp/PyYAML) — the exact
