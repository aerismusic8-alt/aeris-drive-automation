## The admin agent was watching a number that did not exist

K asked why AR was not minding the Page — "แบบนี้ธุรกิจก็เริ่มต้นไม่ได้". He was
right, and the cause was worse than neglect: the rail reported *"กล่องข้อความ: มี
รายการใหม่ 2 รายการ"* every hour for days on an inbox that is **completely empty**.
`_count_new()` counted the substring "ใหม่", and the Business Suite inbox carries a
permanent filter chip with that exact label. It was reading the filter UI as mail.

Because it "found" items, it also drafted a canned reply to nobody each run, and —
the expensive part — it never alerted on the number that actually matters. The Page
today: **1 follower, 0 comments**, posting daily. That is the "business has not
started" signal, and it was buried.

Fixes in `aeris938-2/scripts/admin.py`:
- `_inbox_state()` reads the empty-state text ("ไม่มีข้อความ") for 0, a printed
  count for N, and returns **-1 "unknown"** rather than a confident 0 — never count
  a label again.
- `page_snapshot()` now reads **as the Page** (calls `social_stats._switch_to_page`),
  so the follower number is the Page's, not K's profile — the same identity bug that
  made views read 0.
- Digests the real numbers: followers, unread, comments. Drafts only when
  `comments > 0`, so no more replies to an empty room.
- `_stall()` + a "เพจไม่โต" alert (≥3 days, <10 followers), deduped through a
  `stall_alert` flag in the **committed** `admin-log.jsonl` — a side file would not
  survive CI's fresh checkout and the alert would fire hourly.

Live proof: `admin.py --check` now prints `ผู้ติดตาม: 1 / ยังไม่ได้อ่าน 0 ·
ความคิดเห็น 0` and no draft. Tests: aeris938-2 18 passed, music938-1 1103 passed.

Lesson worth keeping: **when a watcher reports activity on a quiet surface, suspect
the watcher first** — same shape as the "0 views" bug and the `Skills.hotbar` empty
list. A count that comes from a label rather than an item is not a measurement.
