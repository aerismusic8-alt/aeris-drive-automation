### Karaoke safety (K: "ถ้าเนื้อร้องไม่ตรงเพลงอย่าทำนะ เสียหาย")
The lyric-led hook made this a hard requirement. `make_short.karaoke_ok(slug)`
refuses a karaoke render when: the karaoke mix is missing, its length differs
from the song by >2% (wrong take / wrong track), the cover is missing, or the
lyric file has no `[chorus]`. `render(mix="karaoke")` raises on a refusal and
`--skip-existing` skips that song, so a batch never ships a mismatched clip.
This is the strongest guarantee a free pipeline can give; syllable timing is not
machine-checkable without paying, and K's line is "do not do it" when in doubt.

### Bugs found while wiring the new format
- `crosspost._slug_of` / `_hook_of` only stripped `short-song-`, so a
  `short-karaoke-01-...` clip would have been captioned with its whole stem and
  every link/lyric line wrong. Fixed to strip both prefixes; `_hook_of` returns 0
  for karaoke (one clip per song).
- `crosspost --merge-queue` is new and must be used instead of `--rebuild-queue`
  for a format addition: a rebuild enumerates gitignored `library/shorts/` and
  would silently drop the committed backlog.

## Trap 4 — a guard on an ignored file never fires (2026-11-07)

The compilation job skips when `compilation-state-<stem>.json` carries a
`video_id`, but `music938-1/work/*` is gitignored, so a fresh CI checkout has no
state file, the guard sees nothing, and the monthly job would render and publish
another near-identical album. Fixed by un-ignoring `compilation-state-*.json`
(and committing the current one). **When a CI job's decision depends on a file,
that file must be tracked** — an ignored guard is a silent no-op.

Proved on CI: run 42362345871 (`ae3e27a3`) went green with every render/upload
step `skipped`, while the two earlier runs on un-guarded commits were cancelled
before they could upload a duplicate.
