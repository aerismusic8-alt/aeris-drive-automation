### ⚠️ The thing that cost the most time: `BUILD_REF` lies, and the branch is what ships

`AX PC1 Roblox Publish` logs `BUILD_REF=main`, and it is easy to read that as "main was
published". It was not. `AX_PC_CONTROL/pc1-roblox-build.ps1` has
`$BRANCH = 'ax-arena-roblox-game'` **hard-coded**, so the *script* is fetched from the
ref you passed while the *code it builds* always comes from that branch:

```
BUILD_REF=main
HEAD is now at 967753a Temporary: dump both universe objects from the live-state job
Building project 'AXArena'
SOURCE_BLOCKS=39   SCRIPT_INSTANCES=39
```

`SOURCE_BLOCKS=39` = the branch's `roblox/` (32 shared + 5 client + 2 server). `main`'s
`roblox/` has 28 files (24 + 2 + 2). **The two refs are different games.** They diverged
at `6f2e48b` (2026-10-19); `main` is 35 ahead / 135 behind the branch. `main` holds the
newer Ragnarok-systems work (`Config.Version = "1.0.0"`); the branch holds a bigger tree
(`Config.Version = "1.0.1"`, plus `roblox-garden/` and `breachline/`) and it is the one
players get.

Consequence: editing `roblox/` on `main` changes nothing that is live. Confirm which tree
owns a file before promising a change reaches players.

### The measurement that was wrong twice

Two sessions concluded "the game is not playable" from
`games.roblox.com/v1/games/multiget-playability-status`. That endpoint reports the
**caller's** state. A logged-out caller gets `GuestProhibited` from *every* Roblox
experience. Proved with a control, which is the part that had been missing:

    383310974   Adopt Me!    GuestProhibited   (234,667 playing at that moment)
    1686885941  Brookhaven   GuestProhibited
    10773483379 ours         GuestProhibited

Four universes, one answer, only shared property = caller not signed in.
**Lesson: any probe that returns the same value for a famous working thing is
measuring itself.** Put a control beside your target in every monitor. The new
`scripts/roblox-live-state.py` carries Adopt Me in the same record for this reason.

Also checked and discarded: `playableDevices: None` on the public games API looked
like "no device enabled". Adopt Me returns `None` too, with 234k playing. The field
is simply unpopulated there — not a signal. Same trap, caught by the same habit.

### The real gate: it is a form, not a payment

`get-age-recommendation` for 10773483379 -> **"Content May Vary", minAge 16**.
Roblox's own doc (`production/promotion/content-maturity`): *"Games with a Content
May Vary label are only accessible to age-checked Roblox users ages 16+."* So the
16+ ceiling is **self-inflicted** — the questionnaire is incomplete.

The previous write-up had the order backwards. Correct order
(`production/publishing/kids-and-select`):
1. Complete the **full** Maturity & Compliance questionnaire — **free, and the
   blocking step**. The first page alone yields 16+.
2. Label must become Minimal/Mild/Moderate for younger tiers to be eligible.
3. **Only then** the fee/subscription and the 250-engaged-player evaluation apply.

AX Garden Legends is already `Minimal` and has 3 visits, so its ceiling is
**discovery**, not permission. That is the distribution problem, not a Roblox gate.
