# 2026-11-26

## Image bank was dead for three days (found + fixed, PR #59)
Symptom: `ax-image-bank` cancelled at the 120-min cap six ticks in a row
(11-24..11-26). Manifest's newest row = 2026-11-23; **all 332 cursors = 0**.
Cause in `ops/image_bank.py::harvest`: `exhausted` reset on *any* non-empty page
(a page of already-held titles is not progress), and `cursors[q]` was saved only
inside the kept-batch branch → every run restarted at offset 0 and re-walked the
same pages until killed.
Fix: two consecutive stale pages end that query; cursor saved every page;
`--budget-s 5400` (rail) leaves 30 of the 120 min for shard+commit; logs flush.
Test `test_image_bank_harvest_is_bounded` pins all three.
Lesson (again): a green/cancelled run says nothing about output — check the
manifest's last row date, not the run list.

## Outcome of the 11-26 verification (bank) — the surface is saturated
Run `45833958408` (branch, 90-min budget) **succeeded**: manifest
8,679 → 8,743 (+64), shard 17 → 18, commit `87ca977`. First growth since 11-23.
Why it took the whole budget: **Commons search has one page per query**.
`gsrlimit=500` answers with 13-49 usable hits and **no `continue` token**;
`gsroffset=250` returns 0 pages. All 332 queries are spent after page 1 —
8,743 ≈ 332 × 26 *is* the whole surface. So the bank now marks a spent query
and re-tries it after a week (`is_spent`), and a saturated bank answers in
seconds instead of holding a runner for two hours.
To grow again: **new search terms**, or `generator=categorymembers` (paginates
properly, hundreds of thousands of CC images) — a separate, larger change.
