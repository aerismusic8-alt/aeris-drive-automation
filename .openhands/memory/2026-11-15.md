## Produce loop wedge — fixed and pushed (2026-11-15)

content engine (no FB, no desktop needed): **the produce loop could wedge**.

`produce_loop.pick_theme` keys off `title`, but a `no-draft` record carried only
the `slug` — so a theme whose lyric draft kept failing was re-picked on every run
and the loop never reached the other ~60 themes. Evidence in
`work/produce-queue.json`: `30-khuen-thi-yang-mai-lap-v30` appears 8× as
`no-draft`, no song made. Silent because `pick_theme` never returns `None`, so the
"pool exhausted" line never prints, and the rail step is `continue-on-error: true`
(so a green run and a stalled loop look identical).

Fix: `make_one` writes `title` on every result; new `attempted_titles(q)` skips a
theme only after `MAX_DRAFT_ATTEMPTS` (3) failures, so a transient failure (a
pollinations 400, or the one-retry success origin logged for `32-...-v32`) still
recovers. Committed `464aa22`, pushed to origin/main (rebased over 19 upstream
commits; the parallel sessions had not touched this file). 22/22 produce checks
