## The pipeline was silently publishing NOTHING for a day (two stacked blockers)
K asked twice for status. The honest answer was "nothing new shipped", and the cause
was not the code I had been polishing — it was two environment/infra gaps.

**1. A missing `numpy` turned into "retired engine" skips.** `release.py` calls
`provenance.verdict()` to refuse songs rebuilt by the rejected Piper engine. That
module imports numpy. On a fresh pod numpy was absent, the import raised, and
`is_retired` **fails closed** — it prints "provenance check unavailable
(ModuleNotFoundError); skipping the song rather than risk the retired engine" and
skips *every* song 39-48. A whole day of the release rail was green (rc 0) and
uploaded nothing. Lesson: `provenance check unavailable` in the log is a broken
pod, not a verdict. Install numpy first.

**2. `release.short_files()` only lists hook cuts that are RELEASE ASSETS.** It
scans `_release_asset_names()` for `short-<mix>-h*<slug>.mp4`; a file sitting on
local disk is invisible unless its plain name matches. So a freshly rendered Short
is not plannable until `scripts/publish_media.py` pushes it to the `media-938`
release. That is the actual gap between "rendered" and "queued".
- `python3 scripts/publish_media.py --dry-run` then with no flags (idempotent,
  skips names already present). Needs `AX_GH_TOKEN`.
- Verified: after uploading 16 files for song 48, `release.py --plan --shorts`
  finally printed `SHORT 48-luai-mai-yut-v48`.

**Upload walls that are real, not bugs.** `release.py --next` refused with
"today's uploads are done: 2/2" — the cadence cap (`UPLOADS_PER_DAY=2`) on the
Pacific day, not a quota error. A `READ FAILED 403 ... exceeded your quota` line
right after it is the shared 10k API pool, and it is *separate* from the upload
cap; a live `yt_auth.get_videos` probe still answered 200, so always probe before
believing a 403 means the rail is dead.

**Env for a fresh pod (add to the recovery list).**
- `pip install numpy` (provenance, make_song, several rails)
- `apt-get install fluidsynth musescore-general-soundfont fluid-soundfont-gm`
- ffmpeg/ffprobe: prepend `/workspace/ax-tools/ffmpeg/ffmpeg-master-latest-linux64-gpl/bin`
- `export YT_CLIENT_ID YT_CLIENT_SECRET YT_CH3_REFRESH_TOKEN` for an upload; the
  refresh token alone fails 400 "Could not determine client ID".

**Backlog found while checking.** 16 songs have an mp3 but no Short asset at all
(16-21, 25-27, 32, 33, 44-47, 49). Rendering them is free and fills the queue; 49
also has no cover yet.

## Gemini review became real (2026-11-19, ~05:40 UTC)

The Gemini-pass rule is now enforced by a working reviewer, not a stub.

`ops/gemini_review.py` (new) renders a labelled contact sheet (8 frames + t=)
and asks the signed-in Gemini web app to score the clip 1-10. Records through
`gemini_gate.record()` hash-bound to the exact file sampled.

**Gemini cannot open a video file** even signed in — it answers "ไม่มี
ความสามารถ". The image route is the only one. Send the *measured* facts with the
pictures (motion, caption count, LUFS, TP): a still cannot show motion, so
asking Gemini to judge motion from a sheet is asking it to guess.

Four bugs that each cost a run:
1. `Runtime.evaluate` with `returnByValue=True` returns no `objectId`, so
   `DOM.setFileInputFiles` had nothing to address. Pass `returnByValue=False`.
2. Gemini mounts **no** `input[type=file]` until "Upload & tools" is clicked;
   clicking mounts 4, and the third accepts `image/*,video/*`.
3. The desktop's Gemini UI is **Thai** — the send button is "ส่งข้อความ", not
   "Send". A `/send/i` selector finds nothing and the prompt sits unsent.
4. Reading the last `message-content` in an old chat returned a previous answer
   ("2+2 = 4"). Navigate to `/app` first and wait for `COUNT_MSGS > before`.

**Caption measurement trap.** `make_short.py` burns the ASS into the picture, so
`ffprobe -select_streams s` reports **0** for a clip full of lyrics. The burned
file is `music938-1/work/<slug>/short-song-<hook>.ass`. Verified: song 48 h1 has
10 Dialogue lines, 44/45/46/47 have **3** (hook card + follow ask only — no
lyrics at all). Never glob for the `.ass`; parse the slug from the clip name or
you will report another song's captions.

**Google session: `login_vault.py restore` alone was not enough.** It restored
210 cookies but reported `.google.com: SESSION REJECTED`. `ops/session_guard.py`
then printed `google revived` — that is the step that actually re-establishes
the session (`_revive_google`, AUTO_REVIVE includes "google"). `check_login.py`
then gave `RESULT=SIGNED_IN account=aerismusic8@gmail.com`. Also: the vault key
is `axlogin:index`, not `login_vault:index` (I read the wrong key first and
concluded the vault was empty).

**Verdict so far: song 48 h1 = 4/10 FAIL.** Gemini's reasons: blurred top and
bottom bars mean it is not full-frame/premium; the same root-and-light image
repeats for the whole clip; Thai captions are readable and uncropped. That is a
real defect in `make_short.py::chain()` — the blurred `[bg]` fill and a single
static cover.
